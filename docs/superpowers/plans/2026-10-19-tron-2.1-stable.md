# TRON SDK 2.1.0 Stable Release Plan

> **For agentic workers:** Use superpowers:executing-plans for inline execution, then one independent final code review.

**Goal:** Prepare and release only `@bankofai/x402-tron` and `@bankofai/x402-tron-extensions` at `2.1.0`, with an explicit migration contract and repository-compliant PR/CI/release history.

**Architecture:** Preserve the official Core mechanism/independent extension boundary already validated in beta.2. First restore the missing 2.0 release back-merge, retain its Agent Wallet 3 support, integrate the SDK feature through develop, and prepare the stable artifacts on `release_v2.1.0`.

**Tech Stack:** TypeScript, pnpm 11.1.1, official Core 2.28.0, npm, GitHub PR checks.

**Spec:** User request on 2026-10-19 and `BRANCHING.md`.

## Global Constraints

- Both publishable TRON packages and the extension's exact mechanism dependency are `2.1.0`.
- Only these two packages are published; existing Core/EVM/HTTP/legacy packages keep their released versions.
- Preserve released 2.0 transaction-artifact compatibility when integrating main and the beta migration.
- Disclose required Core/HTTP/MCP/resource import migration; do not claim a zero-change upgrade from 2.0.
- No peripheral service edits, deployment, mainnet transaction, credential output, or protection bypass.
- Stable publication follows release branch → reviewed, passing PR → main → tag/artifacts/publication → develop back-merge.

## Review Focus

- Agent Wallet 3 artifact envelopes and malformed/cross-family signatures retain the 2.0 behavior; preserve/add regression cases.
- Mixed old and official Core objects are excluded from the migration contract; compile actual consumer/example imports.
- ESM/CJS exports, strict declarations, and extension dependency rewriting are checked using final tarballs.
- Consuming Changesets must not schedule unrelated old Core/package publication; inspect the resulting package/version diff.
- Only the exact reviewed main commit and its artifacts may be tagged/published; verify registry versions, tags and integrity.
