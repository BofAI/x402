Date: 2026-10-19 (Asia/Shanghai). The requested scope was to publish both beta packages on the 2.1 version line and review the code. Source: feat/tron-official-sdk; artifact commit 9829cb6b6cf8797f057b445b66f7cfd728353805.

## Versions and migration boundary

Both packages are 2.1.0-beta.1, with an exact official Core peer of 2.28.0. The extension depends on the exact same mechanism version. Published 3.0.0-beta.1 artifacts remain historical releases. This migration beta requires changes to Core/HTTP/MCP imports, resource runtime imports, and explicit extension registration; it does not claim an unchanged-source upgrade from 2.0. Changesets computes 2.1.0 as the stable target for both packages.

## Review and fixes

- SDK batch checks the resolved atomic cap against both the initial request and final deposit, covering EIP3009, Permit2, and custom strategies. GasFree checks value+maxFee before signing, including activation fees; skipBalanceCheck does not bypass the cap. Default batch deposits above the cap are rejected; callers can explicitly select a smaller strategy or adjust the cap.
- Facilitator serializes signing and broadcast per network/EOA within one process, retaining nonce reservations. An uncertain broadcast freezes allocation until the pending nonce advances beyond it. Failures before signing do not reserve a nonce. Source commit 1265542; no claim of cross-instance or restart nonce recovery.
- Gateway timeouts cover response bodies. An upstream body timeout after settlement preserves settled:true and PAYMENT-RESPONSE. Source commit 16bc72b.
- Both module fields now point to the existing dist/esm/index.mjs. Clean artifact checks cover main/module/types and every export.
- An independent reviewer reran cap 6/6, wallet 7/7, and body timeout 16/16 tests, finding no new blocking payment logic issue. The module field finding was raised to P2 based on consumer build impact and fixed. Entrypoint existence checks failed before the fix and passed afterward; packed consumer validation was repeated.

## Known limitations

- Upto still used optimistic preflight on allowance/balance RPC failures; explicit rejection was required before stable release.
- EVM nonce allocation was coordinated within one process only. Replicas sharing a wallet need an external allocator. Reconcile uncertain broadcasts before retrying; do not restart to blindly submit replacements.
- Gateway did not add automatic cross-instance delivery recovery. Interrupted post-payment requests still require reconciliation by original nonce/txID.
- No live chain transactions were initiated in this run. Historical Nile acceptance used the 3.0.0-beta.1 client and the official deployment at that time; it does not prove deployment of the upgraded Facilitator or live-chain retesting of 2.1.
- Mechanism latest remained 2.0.0. Extension latest was previously 3.0.0-beta.1; this run published only the beta tag. Install an explicit version or beta.

## Decisions

- Follow the requested 2.1 migration beta line and retain separate M1/M2 boundaries. Do not restore all resource runtime exports at the mechanism root through a circular dependency. Consumers must migrate imports; this is not a 2.0 drop-in or stable compatibility acceptance claim.
- Pending TRON Changeset bumps were changed to minor, retaining the separate legacy Core patch. The fixed group stable target was verified as 2.1.0. Version planning does not waive subsequent stable-release source compatibility requirements.
- The invalid module field was raised from the reviewer's minor finding to P2 and fixed because older bundlers could fail to build entirely. Entrypoint assertions failed then passed, and final tarball consumer validation was repeated.
- Publication was explicitly authorized and used existing npm authentication, without additional confirmation or credential writes.
- No new minor review finding was deferred. The upto, source compatibility, cross-instance, and live-chain boundaries above remained explicit; beta validation is not stable acceptance.
