## 走读及修复

- SDK Batch按初始请求和最终充值额检查resolved atomic cap；覆盖EIP3009、Permit2和自定义strategy。GasFree签名前检查value+maxFee，包含账户激活费；skipBalanceCheck不绕过cap。默认batch充值超cap时拒绝，调用方可显式选择更小strategy或调整cap。
- Facilitator进程内按network/EOA串行签名与广播，保留nonce预留；不确定广播后冻结，pending nonce越过后才恢复。签名前失败不占nonce。源码提交1265542，不声称跨实例/重启nonce恢复。
- Gateway超时覆盖响应正文；已结算后的上游正文超时保留settled:true及PAYMENT-RESPONSE。源码提交16bc72b。
- 两个包module字段修正为实际存在的dist/esm/index.mjs，冷制品检查覆盖main/module/types和所有exports。
- 独立reviewer重跑cap6/6、钱包7/7、正文timeout16/16；未发现新的支付逻辑阻断问题。将module字段问题按实际消费构建影响提升为P2并修复，入口存在性RED→GREEN，重新完成packed消费者检查。

## 已知限制

- upto allowance/余额RPC异常仍沿用预检乐观行为；稳定版前应改为明确拒绝。
- EVM nonce分配只在同进程内协调；共享钱包多副本必须使用外部分配器。广播结果不确定时应先对账，不能通过重启盲目补发。
- Gateway未新增跨实例自动补交付。支付后链路中断仍需依据原nonce/txID对账。
- 本轮未发起真实链交易。历史Nile验收属于3.0.0-beta.1客户端与官方当时部署，不代表新版Facilitator已部署，也不代表2.1实链复测。
- 机制latest保留2.0.0。扩展原latest为3.0.0-beta.1，此次只发布beta标签；安装使用明确版本或beta。
