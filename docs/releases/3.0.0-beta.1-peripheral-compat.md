# 3.0.0-beta.1 外围服务兼容验证

日期：2026-10-16。范围：Facilitator、Gateway、Catalog 的本地完整链路与新旧 SDK
互操作；未部署或发布外围服务。所有 SDK 均来自 npm registry 的精确版本。

## 结论

经过必要接入迁移，已验证范围内的 v2 HTTP 消息、资源扩展 v1 wire、已有配置和
资源账本可继续使用。**源码不是原样替换依赖即可兼容**：Facilitator 必须统一使用
官方 Core，迁移资源导入与注册工厂；Gateway 必须迁移 HTTP codec。

本地隔离与官方当前部署的 **Nile 实测已完成**：ordinary Permit2、upto、batch、GasFree、
低 allowance 的双资源代付/回收均通过。官方部署不公开 SDK/build 版本，不能据此宣称
升级后的本地 Facilitator 已部署并通过实链验收；EVM 广播也未包含在本轮 Nile 测试中。

## 验证发现并修复的问题

- 官方 EVM 注册助手额外注册 24 条 v1 网络，导致 `/supported` 与本服务 v2-only HTTP
  能力不符。改为逐配置注册 v2 类；完整支持集合测试先失败后通过。
- 官方 EIP-3009 verify 移除了旧异常归一化，坏输入从协议失败变成 HTTP 500。
  服务仅在该 verify 分支恢复原状态/错误码，返回固定错误描述；Permit2/settle 仍由官方实现负责。
  malformed、真实签名与 RPC 失败回归通过，不声称恢复所有旧 settle 错误文本。
- **Nile 实测发现 Gateway 10 秒默认超时不足**：首次资源请求返回 504，官方实际完成了结算，
  上游未交付。按原 nonce/txID 核对，没有重复付款。修复为仅启用资源的 TRON exact Permit2
  路由且实际携带扩展时使用 `max(240000, 全局超时)`；专用
  `X402_GATEWAY_RESOURCE_SPONSORING_TIMEOUT_MS` 明确覆盖。普通请求和入站窗口保留原值。
  14 项延迟/配置回归通过，新零 allowance payer 再次实测成功交付并回收两类资源。

独立代码审查发现前两项，均已有 RED→GREEN 和最终完整套件证据；Nile 发现的第三项也先复现、
补回归再修复。最终源码与测试全部保留在分支，未推送、合并或部署。

## 互操作与恢复

- SDK2 真实 exact 签名 → 新 Gateway/Facilitator → 成功结算/交付；SDK2 upto / batch
  deposit/voucher 静态真实签名也经升级后实际 HTTP/Core 完成验证、claim 与实际金额结算。
- SDK3 普通签名 → 旧 SDK2 mechanism → 成功；SDK3 signed Approval → 新旧同能力
  Core/mechanism/extension 组合均完成一次代付、结算和交付。
- 旧 Facilitator 未配置资源 runtime 返回 `sponsor_runtime_unavailable`，这是能力配置差异。
- 官方 EVM Base EIP-3009 与 GasFree 本地 HTTP relayer 链路通过，链广播/确认注入。
- Facilitator 实际 HTTP 层验证 TRON upto 的实际结算金额、零金额、超额/错误签名/replay/
  pending；batch deposit/voucher/claim/settle/refund、管理零 timeout、authorizer 签名、
  错误签名/链失败/状态返回通过。Gateway/Catalog 现有路由不包含 upto/batch。
- 联合链路使用实际 Catalog handler、Gateway 与 Facilitator loopback socket，真实
  TIP-712/Approval 校验、PostgreSQL settlement/卖家隔离/advisory lock、SQLite 账本。
  重复 nonce、错误签名、非法 HTTP 字段均拒绝；上游只在成功结算后交付。
- energy/bandwidth 双资源委托 → Approval → settle → 回收顺序通过；广播前账本已写入。
  SDK2 与 SDK3 runtime 留下的未完成债务，关闭并重开 SQLite 后均由 SDK3 恢复，
  未重复广播 Approval。存储格式/实现未改，仅迁移资源类型导入。
- PostgreSQL 共享协调、并发预算/容量、重启、RPC/锁连接故障、原 txID 恢复、权限与
  回收锚定由实际服务回归测试覆盖。

## 限制与后续验收

Catalog 联合 fixture 将生产发现地址/网络映射成本地 Nile 路由，使用固定测试价格；
不代表线上部署、生产定价或公网业务 API 可用。本地联合测试的链读取/广播/确认与资源可见性
为明确注入边界；钱包签名、SDK/Core、HTTP、数据库逻辑实际运行。Nile 章节使用真实链 I/O。

batch ChannelManager 原始 refund 管理消息 `extra:{}` 在 `/verify` 缺 authorizer 元数据，
直接 `/settle` 正常；旧 SDK2 同样如此，管理器自身走 `/settle`，不是此次回归。
Beta 已知 upto 余额/allowance RPC 异常时预检偏乐观行为未在此次服务迁移中修改。

下一步如验收部署后的新版 Facilitator，需要明确其 SDK/build 版本并执行独立部署验收。
本轮没有重启官方服务或访问其 resource 私有账本，恢复/并发/锁失效依赖本地真实存储测试证据；
链上只确认了实际委托、Approval、结算和回收。Gateway 没有新增跨实例自动补交付/幂等恢复；
任意网络中断仍须先按原 nonce/txID 对账，不能直接生成新付款。官方 EVM pending store 的
跨实例/重启恢复与 TRON 自定义 EIP-3009 token 实链也未据此声称验收。
